# 21. 고해상도 타일맵 · 비도트 그래픽 제작 규격

> 상태: ✅ 제작 기준 확정 · 2026-10-15 · 지형 이미지 256×256px/칸 · 다중 타일셋 · 고해상도 직접 렌더링.
> 해상도·단위에 관한 문서 공통 기준이다. 기존 HTML의 구현 수치와 최종 제작 규격을 구분한다.

### 2026-10-16 · 현재 Unity 맵 프로토타입 적용값

사용자 지정에 따라 `Book/Assets/Scenes/World12Prototype.unity`에는 **128×128px 타일, PPU 128, 1칸 = 1유닛**을 적용한다. 1920×1080에서 **한 칸이 128×128 화면 픽셀**로 보이도록 Orthographic Size를 **4.21875**로 설정한다. 시야는 **15×8.4375칸**이며, HTML의 원래 30×16.875칸 시야보다 두 배 확대된다. 플레이어 판정 0.75×1.375유닛은 그대로이므로 화면에서는 96×176px다.

아래의 256px는 기존 아트 마스터 규격으로 유지한다. 현재 Unity 프로토타입의 가져오기·카메라 설정에는 이 절의 128px 값이 우선한다. 원본 이미지를 128px로 축소하며, HTML의 저해상도 렌더링을 확대하지 않는다. 바닥 원본의 4px 윗면 띠는 128px 파생 이미지에서 2px다.

현재 씬은 HTML `Prototype/unfin_world.html`의 560×215칸과 원본 배치를 옮긴 **맵·이동 검증용 프로토타입**이다. 그래파이트·크레파스 지역별 바닥/벽 A/B/C 변형을 사용하며, 방 장식·장면 조명 및 전투 시스템은 별도 제작한다. 실행과 검증은 [Book/README](../Book/README.md)를 따른다.

모서리와 계단에는 **8방향 이웃 기반 47종 연결 타일을 지역별로 적용**한다. 윗면·좌우면·아랫면을 동시에 처리하고 대각선 빈칸의 안쪽 모서리도 채운다. 128px 파생 이미지의 표면 띠는 2px, 바깥 모서리 둥글림은 최대 3px로 제한하며 충돌 칸은 유지한다. 연결 재질은 방향별 노출 거리로 혼합하고 지중은 거의 검정으로 수렴시킨다.

현재 활성 원화는 `Art/samples/regional-variants-v6/`다. 잔입자·가는 선을 줄인 큰 흙덩어리와 넓은 명암 면을 사용한다. 지역별 A/B/C 3패턴 × 47연결 모양, 두 지역 총 282종이다. 패턴을 고정된 불규칙 순서로 섞으며 접합부의 높이와 색을 맞춘다. 표면부터 타일 끝까지 서서히 어두워지고 마지막 8px에서 내부색과 연결된다.

**v6 표면 규칙이 앞뒤의 기존 2px 직선 띠 규칙보다 우선한다.** 밟는 윗선·벽 윤곽은 원화의 얕은 요철을 살려 128px 기준 최대 3px 들어가게 만든다. 일정한 띠나 원근 윗면을 덧그리지 않는다. 충돌 격자와 카메라 배율은 그대로이며 시각적 윤곽과 판정면의 차이는 최대 3px다. 256px 마스터는 같은 비율인 최대 6px 요철을 사용한다.

## 1. 충돌 칸과 이미지 픽셀은 다른 단위

**타일맵은 이미지를 격자에 배치하는 방식이며, 도트 그래픽을 뜻하지 않는다.** 이미지 픽셀 수를 높이고 매끈한 선과 면으로 그리면 타일맵으로도 선명한 비도트 그래픽을 만들 수 있다.

- 지도와 충돌: **1칸 = Unity 1×1유닛**. 맵 좌표, 점프 거리, 통로 폭은 칸/유닛으로 설계한다.
- 기존 HTML: 1칸을 **16 논리 단위**로 계산한다. 기존 문서의 물리 수치에 남은 `px`는 이 논리 좌표다. 실제 이미지의 픽셀 수가 아니다.
- 최종 지형 이미지: **1칸용 그림 256×256px, PPU 256**. 16×16px 또는 32×32px 그림을 확대해 사용하는 방식은 금지한다.
- 선택적 고밀도 원본: 512×512px/칸으로 제작할 수 있다. 256으로 축소해 내보내거나, 512 원본을 그대로 가져오면 **PPU 512**로 설정해 1유닛 크기를 유지한다.
- 변환식: `월드 유닛 = HTML 논리 좌표 ÷ 16`, `지형 이미지 픽셀 = 월드 유닛 × 256`. 이동 속도와 가속도도 같은 공간 배율로 환산하며 시간은 바꾸지 않는다.

## 2. 화면과 캐릭터

카메라 기본 시야는 **가로 30 × 세로 16.875유닛**, Orthographic Size **8.4375**다. 이미지 해상도를 높여도 방 크기와 캐릭터의 상대 크기는 같다.

- 1920×1080 출력: 1칸이 화면에서 64px. 256px 원본을 1/4로 축소한다.
- 2560×1440 출력: 1칸이 약 85.33px. 정수 픽셀에 강제로 맞추지 않는다.
- 3840×2160 출력: 1칸이 128px. 256px 원본을 1/2로 축소한다.
- **선택한 출력 해상도에서 직접 렌더링**한다. 완성 게임 화면 전체를 480×270으로 먼저 그린 뒤 확대하지 않는다. 480×270은 기존 HTML의 논리 시야일 뿐이다.
- 플레이어 판정은 기존 12×22 논리 단위 = **0.75×1.375유닛**이다. 같은 크기의 시각 기준은 **192×352px, PPU 256**. 그림의 여백과 무기까지 포함한 프레임 캔버스는 512×512px 이상으로 잡되 발 기준점과 캐릭터 키를 고정한다.
- 캐릭터 키의 화면 표시값은 1080p에서 88px, 4K에서 176px다. 원화 키 352px와 혼동하지 않는다. 다른 적·보스도 월드 크기 × PPU로 산정한다.

## 3. 여러 타일맵과 타일셋을 섞는 방법

1. **Collision:** 1유닛 격자의 충돌 정보. 화면에 그리지 않는다.
2. **Terrain Fill:** 구역별 재료 타일셋과 큰 채움 이미지를 배치한다. 기존 A~C 변형을 고정 시드로 섞는다.
3. **Terrain Detail:** 최소 4가지 표면 무늬 계열을 사용한다. 인접 구획의 같은 계열을 피하고, 크기·밀도·간격·위치를 달리한다.
4. **Terrain Edge:** 바닥·벽·천장과 안쪽/바깥쪽 모서리를 따로 구성한다. Rule Tile 또는 같은 역할의 이웃 판정으로 가장자리를 고른다.
5. **Decor:** 여러 칸에 걸친 방 고유 장식과 재료 조각을 덧붙인다. 기능이 없는 장식을 발판처럼 보이게 하지 않는다.

기본 제작 방식은 **고해상도 Tilemap + 여러 타일셋 + 장식 레이어**다. Sprite Shape는 필요한 긴 곡선 구간에만 사용하는 선택 보조 도구이며 필수가 아니다.

256px 그림을 칸마다 똑같이 붙이는 것만으로는 반복이 없어지지 않는다. 2×2·4×4칸을 덮는 그림은 각각 512×512·1024×1024px로 만든다. 기존 2048×2048 채움 원본은 PPU 256에서 **8×8유닛**을 덮는 큰 재료 원본이며, 모든 그림을 단일 칸으로 잘라야 하는 것은 아니다. 2048×512 띠는 **8×2유닛**의 원본으로 활용한다. 모서리·특수 지형 원본은 실제 배치 폭/높이에 맞춰 잘라 내보낸다.

연결용 변형은 공통 테두리를 유지한다. 회전·반전으로 선 방향이나 이음을 깨뜨리지 않는다. 같은 무늬의 연속 배치와 일정한 바둑판 배열을 피하고, 구역 경계는 전환 타일로 부드럽게 섞는다. 종이 배경의 연한 모눈은 세계관 표현이며 지형 타일 경계와 구분한다.

## 4. 그림과 가져오기 기준

[16 아트 컨셉 §0-1](16_아트_컨셉.md)의 v5 방향을 따른다. 할로우 나이트를 참고한 공간 깊이·실루엣·분위기를 고해상도 일러스트로 표현하며, 반복 타일 원본과 장면 조명·안개 레이어를 분리한다.

- 매끈한 곡선, 선명한 외곽선, 둥근 모서리, 절제된 면 음영을 고해상도에서 그린다. 픽셀 브러시·디더링·의도적인 계단선·저해상도 도트 확대는 금지한다.
- 지형 선 굵기는 1080p 화면에서 2.5~3px를 기준으로, PPU 256 원본에서는 **10~12px**로 맞춘다. 큰 캔버스에 작게 그린 도트 이미지를 붙이는 것은 고해상도 제작이 아니다.
- 필터는 Bilinear 또는 Trilinear를 사용하고 Point/Nearest 확대, Pixel Perfect Camera, 픽셀 스냅을 사용하지 않는다. 축소용 밉맵은 아틀라스 여백과 함께 검수한다.
- 타일 아틀라스의 셀 내용은 256×256px. 셀 밖에 최소 4px 이상의 색상 확장 여백을 두고 실제 밉 단계·축소율에서 이음이 보이면 늘린다. 여백은 셀 크기나 PPU에 포함하지 않는다. 타일 아틀라스는 Clamp, 독립 반복 재료만 필요에 따라 Repeat를 쓴다.
- 바닥 윗면은 판정과 일치시키며 허용 오차는 **0.03125유닛 이하**(1080p 2px, PPU 256 원본 8px)다. 벽/천장 장식의 최대 0.25유닛 돌출은 이동을 오해하게 하지 않는 범위에서만 허용한다.

### 4-1. 지역별 바닥·벽 세트 시안 규격 · 2026-10-15

`Art/samples/regional-pairs-v4`는 5개 지역 각각 바닥 1장·벽 1장, 총 10장의 256×256px 시안이다. 이번 제작 범위에는 천장을 포함하지 않는다. 벽은 왼쪽 지형의 오른쪽 노출 면을 그린다.

- 작화는 사용자 기준 극사실 100 중 **약 75**를 목표로 한다. 이는 측정 점수가 아니라 시각적 방향이다. 세밀한 사진 입자와 잔균열을 줄이고 넓은 면·굵은 재료 결로 정리한다.
- 주요 문양은 이전 시안보다 약 20% 크게 읽히도록 구성한다. 내보내기에서 새 원화의 정면 단면을 약 **1.2배** 확대하며, 표면 띠는 이 확대와 별도로 고정한다.
- **바닥 윗면 띠: 가로 256px × 세로 정확히 4px, y=0~3.** 그 아래 정면 단면은 y=4~255의 252px이다. 지역별로 띠의 색과 재료만 달라지고 높이·두께는 같아야 한다.
- 윗면 띠는 평행한 수평선으로 유지한다. 넓이가 달라지는 사다리꼴·비스듬한 후퇴선·원근에 따른 깊이 변화는 사용하지 않는다. 충돌 기준은 y=0으로 유지하며, 띠 두께 4px는 충돌 높이나 10~12px 외곽선 기준과 다른 값이다.
- PPU 256에서 표면 띠 두께는 0.015625유닛이다. 1080p 기본 시야에서는 화면 1px, 4K에서는 화면 2px다.
- 원화의 윗면 부분을 정면 단면과 분리하여 4px 띠로 리샘플링한 뒤 합성한다. 프롬프트의 수치 지시만으로 정밀도가 보장된 것으로 간주하지 않는다.
- 접촉 가장자리의 재료는 읽히게 남기고, 지형 내부는 거의 보이지 않는 짙은 불투명 암부로 유지한다. 벽도 공간에서 멀어지는 안쪽으로 어두워진다.
- 바닥 5장을 동일한 y좌표에 나란히 배치하여 띠의 두께와 기준 높이를 검수한다. 각 지역 바닥·벽의 색·결·명암을 한 쌍으로 확인한다. 이 시안은 모서리·전환·반복 변형까지 완성된 자동 타일셋을 뜻하지 않는다.

## 5. 큰 배경과 기존 자동화

기존 배경 배치를 보존하기 위해 L1 뒷벽·L2 세트·L4 전경·방 전체 장식 오버레이는 **PPU 128**을 유지한다. 예를 들어 2048×2048 뒷벽은 16×16유닛, 3840×2160 방 장식은 30×16.875유닛이다. 이들은 한 칸짜리 지형 타일이 아니다. 더 선명한 배경이 필요하면 **그림의 가로·세로 픽셀과 PPU를 함께 2배**로 늘려 배치 크기를 보존한다.

현재 `Tools/unity/Editor/UnfinArtImporter.cs`는 PPU 128 공통 설정을 사용한다. **아직 최종 지형 PPU 256 분류를 구현한 상태가 아니다.** Unity 적용 때 지형·캐릭터 256과 큰 배경/방 오버레이 128을 분리하고, 이미지 교체 뒤 월드 크기를 검증해야 한다. 배경 매니페스트의 128은 배경 전용으로 유지한다.

HTML은 v32 충돌 격자와 절차적 그래픽 검증용이다. 이 문서 수정만으로 최종 고해상도 이미지 타일셋 제작이나 Unity 적용이 완료된 것은 아니다. 현재 589개 에셋 목록은 큰 원본 이미지 목록이고, 최종 256px 셀 분할·아틀라스 패킹 수량은 별도로 관리한다.

## 6. 검수

- 1080p·1440p·4K의 실제 플레이 크기에서 선과 곡선이 선명한지 확인한다. 확대 관찰은 보조이며 래스터 그림에 무한 확대 품질을 요구하지 않는다.
- 카메라를 천천히 이동해 타일 사이 밝은 선, 깜빡임, 모서리 틈, 무늬가 따라 움직이는 현상을 확인한다.
- 넓은 바닥·긴 벽·천장에서 같은 무늬가 반복적으로 눈에 들어오는지 확인한다.
- 방/구역 전환, 세이브 재진입, 재시작 후에도 무늬 선택이 유지되는지 확인한다.
- 판정 박스를 겹쳐 밟는 높이·벽 접촉·통로 폭을 확인한다. 이미지 해상도를 높이면서 게임플레이 크기를 바꾸지 않는다.
