## 최종 제작 해상도와 HTML의 구분

[21 고해상도 타일맵 규격](21_고해상도_타일맵_규격.md)에 따라 최종 지형은 **256×256px/칸, PPU 256**으로 제작한다. HTML의 16 논리 단위/칸과 480×270 논리 시야는 이동·동선 검증값이다. 현재 캔버스 3배 렌더링을 최종 출력 규격으로 사용하지 않는다. 최종 Unity는 선택한 1080p·1440p·4K 해상도에서 직접 렌더링한다. 이번 문서 개정은 HTML 충돌·물리나 Unity 가져오기 코드를 변경하지 않는다.

## 🛠️ QA 도구

### 지형 시각 레이어 업데이트

`unfin_world.html`의 일반 바닥·벽·천장은 `terrain_layers.js`의 채움·표면 무늬·가장자리 레이어로 표시한다. 4가지 고정 시드 무늬 계열, 구역별 색 혼합, 둥근 모서리와 3배 해상도 렌더링으로 픽셀 느낌과 반복을 줄였다. 맵·충돌은 v32 그대로이며, 이미지 에셋과 Unity Tilemap 적용은 별도 단계다. 확인 항목은 1·2장 지형 표시, 청크 경계의 이음, 카메라 이동과 재시작 시 무늬 고정, 특수 지형의 기능 구분이다.

| 도구 | 기능 |

### 🔒 진행 검사 (보스 건너뛰기 방지) ✅
지도를 만들 때마다 자동으로 확인하고, 하나라도 실패하면 지도를 만들지 않음.

| 검사 | 막는 타일로 보는 것 | 통과 조건 |
|---|---|---|
| 1장 시작 → 2장 | 낙서 벽 · 덩굴 · 밀랍 벽 · 문 · 덮개 | 2장 땅에 **못 닿아야** 함 (= 1장 보스 → 대시 → 낙서 벽이 유일한 길) |
| 2장 입구 → 기사방 · 출구 | 물감 문 · 과녁 문 · 밀랍 벽 (덩굴·낙서 벽은 통과) | 기사방·3장 출구에 **못 닿아야** 함 |
| 물감 문 연 뒤 → 3장 출구 | 밀랍 벽 · 밀랍 수직굴 속 | 기사방엔 닿고, 출구엔 **못 닿아야** 함 (= 기사 → 벽타기가 유일한 길) |
| 모든 능력 → 전부 | 일반 벽만 | 수집품·세이브·리본 **전부 닿아야** 함 (지형 바꾸다 입구가 막히는 것 방지. 리본 전용 30번 굴 제외) |

> 중력 없이 칸끼리 이어졌는지만 보는 검사라, "점프로 못 오르는 높이" 같은 건 따로 봐야 함 (밀랍 수직굴 속은 막힌 칸으로 처리).

## 탐험 진행 검증 · 2026-10-21

`Tools/add_exploration_routes.cjs`는 원본 지도에 새 순환로를 적용하고 HTML과 독립 지도를 동기화한다. `ExplorationLayout.json`은 셀 변경 이력과 발견할 봉인 13곳을 보관한다. `ExplorationValidation`은 시작 능력 잠금, 봉인 기록, 대시·연필 깎기·패링에 의한 실제 충돌 제거, 2지역 벽타기로 1지역 밀랍 벽 오르기, 방패·회복 아이템 효용, 사망 후 진행 유지, 새 승강로 점프 15개를 검사한다. 기존 중간층 점프 39개도 함께 검사한다.

`Tools/check_exploration_web.cjs`는 실제 웹 게임에서 미해금 지도 → 보상 획득 → 재방문 표시 → 봉인 개방, 지도 핀, 서재 보상과 밀랍 벽 복귀를 확인한다. 일반 몬스터 애니메이션은 유지한다. 보스·엘리트의 기존 표식 전투는 현재 탐험 프로토타입의 보상 수신기를 사용하며, 이번 작업이 새 보스 AI를 구현한 것은 아니다.

## 해상도별 UI 검증 · 2026-10-28

- 실행: 로컬 WebGL 서버를 켠 뒤 `node Tools/check_ui_resolutions_web.cjs`.
- 지원 해상도: 1366×768, 1920×1080, 1920×1200, 2560×1080, 2560×1440, 2560×1600, 3440×1440, 3840×2160.
- 낮은 해상도로 강제 렌더링하지 않고 실제 캔버스 버퍼 크기를 확인한다. 타이틀 설정에서 각 해상도를 직접 선택하고 확정한다.
- 타이틀, 새 이야기·이어하기, 화면·소리·조작 설정, HUD·미니맵, 지도와 메모 입력, ESC 메뉴, 상호작용 확인, 교환소를 캡처한다. 캔버스 및 메모 입력창 경계, 메뉴 클릭과 일시정지 상태, 브라우저·Unity 오류를 검사한다.
- 4K 버퍼를 작은 창에 표시하는 경우와 전체 화면 전환도 확인한다. 해상도는 미리보기 후 ‘저장하기’로 확정하며 설정을 닫았을 때 유지되는지 확인한다.
- 결과와 이미지: `Book/Validation/ui-resolutions/`. 실제 GPU의 성능 측정이나 Windows 독립 실행 빌드 검증과는 구분한다.
- 웹 전체 화면 버튼을 우측 하단 여백으로 옮겨 우측 상단 미니맵의 구역 이름과 겹치지 않도록 했다. Unity WebGL 템플릿과 현재 로컬 실행 빌드에 동일하게 적용한다.
- 창 축소 시 WebGL 실행으로 JavaScript resize 처리가 지연되어도 캔버스가 넘치지 않도록 표시 크기는 CSS 뷰포트 단위로 계산한다. 선택한 렌더링 해상도와 화면 비율은 유지한다. `Tools/check_webgl_viewport.cjs`는 resize 이벤트를 제거한 상태에서 해상도 8종 × 창 크기 5종의 경계를 검사한다.
- 검증 결과: 실제 WebGL 캡처 122장, 지원 해상도별 필수 화면 13종 전부 확인, 브라우저·Unity 예외 0건. CSS 크기 변경 40조합도 통과했다. 검사한 화면에서 UI 잘림을 발견하지 않았으며, 전체 화면 버튼의 미니맵 겹침과 급격한 창 축소 시 크기 반영 지연을 수정했다.

## 해상도 미리보기와 저장 · 2026-10-29

- 타이틀과 게임 중 ESC 설정에서 화살표는 경고창 없이 즉시 해상도를 적용한다. 기존 12초 확인/자동 복원 기능은 제거했다. 화면·소리·조작 탭 전환은 미리보기를 유지한다.
- ‘저장하기’만 해상도를 영구 저장한다. 뒤로가기·ESC·설정 종료는 저장하지 않은 변경을 마지막 저장값으로 돌린다. 저장 후 다시 수정한 경우에도 가장 최근 저장값으로 복원한다. 다른 설정의 자동 저장은 미리보기 해상도를 함께 저장하지 않는다.
- Unity 검사: `ResolutionPreviewValidation.RunAndBuild`, `Book/Validation/resolution-preview.json`. 8개 선택값, 연속 변경 취소, 기본값 취소, 다른 설정 저장과의 분리, 저장값 재로드를 통과했다.
- 실제 WebGL: `node Tools/check_resolution_preview_web.cjs`. 렌더 버퍼 크기를 강제하지 않고 1366×768·1920×1080·1920×1200 전환을 확인했다. 마우스·키보드 입력, 13.5초 후 미리보기 유지, 탭 이동, 저장/취소, 기본값, 게임 중 설정, 새로고침 후 저장값 유지/미저장값 폐기 등 20개 확인 항목을 통과했다. 브라우저·Unity 예외 0건. 결과와 캡처는 `Book/Validation/resolution-preview-web/`에 보관한다.
